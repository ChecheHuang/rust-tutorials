# 故事版：奶奶的烘焙廚房與小紙條食譜 🍪

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「週末到奶奶家烤餅乾」的故事，幫你「感覺」出函式、最後一行就是回傳值、閉包、捕獲環境、`Fn` / `FnMut` / `FnOnce`、`move`、高階函式、回傳閉包和 `fn` 指標是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 掛在牆上的食譜卡

奶奶的廚房牆上掛著好多張**食譜卡**。其中一張寫：

> 「**放進 2 匙麵粉和 3 匙糖** → 端出**混好的 5 匙粉**。」

小廚照著做：材料放進去，最後**端出來的那一盤**，就是這張食譜的成果。

> 這就是 **函式**：`fn add(a: i32, b: i32) -> i32 { a + b }`。參數是放進去的材料，`-> i32` 是會端出什麼，最後一行 `a + b` 就是端出來的那一盤。

### 有句點的步驟、沒句點的成品

奶奶的食譜有個小規矩：每一個**步驟後面都畫句點**（「打蛋。」「攪拌。」），只有**最後端出去的那一盤沒有句點**。

小廚有一次在最後一行也畫了句點，奶奶說：「畫了句點就表示『做完了，但沒端出去』喔，客人會拿到**空盤子**。」

> 這就是 **statement vs expression**：有分號 `;` 的是步驟（statement），沒分號的最後一行是成品（expression）= 回傳值。`double_block` 裡連 `{ let temp = x * 2; temp + 0 }` 這種小區塊都會端出值。要提早端出去才用 `return`，例如「蛋壞了，直接端出 0」。

---

## 隨手寫的小紙條

奶奶不是每次都寫正式食譜卡。有時她隨手撕一張**小紙條**：「**多加一顆**。」交給小廚。

小紙條沒有名字，也沒寫「加的是什麼」，但小廚一看就懂。

> 這就是 **閉包（closure）**：`let add_one = |x| x + 1;`。匿名、短短的，參數型別通常不用寫，編譯器會推。

---

## 紙條會記得桌上的東西

這種小紙條最厲害的地方是：它可以**提到廚房桌上現有的東西**。

奶奶寫：「**看一眼桌上那罐鹽的標籤，唸出來。**」這張紙條用了好幾次，每次都只是**看一眼**，鹽罐一直好好放在桌上，其他人也照樣能看。

> 這就是 **捕獲環境 + `Fn`**：`let print_s = || println!("borrowed: {s}");`。閉包只**讀**外面的 `s`（借用 `&s`），可以呼叫很多次，`s` 外面仍可用。只讀的閉包實作 **`Fn`**。

### 在記分板上畫一筆

另一張紙條寫：「**每烤好一盤，就在冰箱上的記分板畫一筆。**」

這張紙條每次用都會**改動**記分板。所以奶奶說：「用這張紙條的時候，記分板要讓它**一個人**畫，別人先不要碰。」而且這張紙條本身也要標明「會改東西喔」。

> 這就是 **`FnMut`**：`let mut bump = || { count += 1; };`。閉包修改外面的值（借用 `&mut count`），閉包變數本身也要宣告 `mut`。可以呼叫很多次。

### 用掉最後一顆蛋

還有一張紙條：「**把桌上最後一顆蛋打進去。**」

這張紙條**只能用一次**——蛋打下去就沒了，第二次照著做，桌上根本沒有蛋。

> 這就是 **`FnOnce`**：`move || drop(s_for_once)`。閉包把捕獲的東西**消耗掉**，所以只能呼叫一次。

## 把東西裝進便當盒帶走

小廚要去鄰居家幫忙烤，奶奶把**桌上的那罐香草精整罐放進便當盒**，連同紙條一起給他：「這罐現在**是你的了**，帶著它走。」

小廚到了鄰居家，紙條寫「聞一下香草精」，他聞了一次、兩次、三次——紙條還是可以一直用，因為只是聞，沒有倒掉。

但是奶奶回頭想找香草精時，桌上已經**沒有**了。

> 這就是 **`move` 閉包**：`let take = move || println!("moved: {owned}");`。`move` 決定的是「**怎麼帶走**」（整個搬進閉包），不是「能用幾次」。這個閉包只讀 `owned`，所以 `take()` 可以叫兩次，仍然是 `Fn`；但外面的 `owned` 已經不能用了。

---

## 幫手的工作條件

奶奶請了三位幫手，每個人對紙條的要求不一樣：

- **阿明**說：「我會照紙條做**好多次**，所以紙條**不能改東西、不能用掉東西**。」
- **阿華**說：「我也會做好多次，紙條可以**改東西**沒關係，但不能用掉。」
- **阿強**說：「我**只做一次**，紙條寫什麼都可以。」

所以「只看鹽罐」的紙條，三個人都能接；「用掉最後一顆蛋」的紙條，只有阿強能接。

> 這就是 **接受閉包的函式**：`apply_fn<F: Fn(i32) -> i32>`、`apply_fn_mut<F: FnMut(i32) -> i32>`、`apply_fn_once<F: FnOnce()>`。要求越寬鬆（`FnOnce`），能接的閉包越多。關係是 `Fn` ⊂ `FnMut` ⊂ `FnOnce`：只讀的閉包三種都算。寫 API 時能用 `FnOnce` 就別要求 `Fn`。

---

## 一整排餅乾的機器

奶奶有一台**輸送帶**。餅乾一片一片經過，你只要塞一張小紙條給它：「**每片放兩倍巧克力豆**。」機器就每一片都照做，最後還幫你**數總共多少**。

> 這就是 **高階函式**：`nums.iter().map(|x| x * 2).sum()`。`map` 這種函式「吃一個閉包」，對每個元素套用。在 Rust 裡這樣寫沒有額外成本（第 15 章）。

---

## 做一台專屬的小機器

小廚說：「我常常要『**多加 10 顆糖**』，可以幫我做一台專門的小機器嗎？」

奶奶做了一台小機器，裡面**放好了 10 這個數字**，然後把整台交給小廚。以後小廚只要把餅乾放進去，就會自動多 10 顆。

> 這就是 **回傳閉包**：`fn make_adder(n: i32) -> impl Fn(i32) -> i32 { move |x| x + n }`。要用 `move` 把 `n` 帶進閉包，不然函式結束 `n` 就不見了。`impl Fn` 代表「某一種會這樣用的機器」，型別編譯期決定。

### 視情況給不同機器

如果奶奶要**看情況**給「加一顆」或「減一顆」的機器，兩台機器外型不一樣，就要先把它們都**裝進一樣大的紙箱**才好交出去。

> 這就是 **`Box<dyn Fn(i32) -> i32>`**：每個閉包都是不同的匿名型別，要在執行期選一個回傳時，就裝進 `Box` 變成 trait object（第 12 章）。

## 不提桌上任何東西的純食譜卡

奶奶說：「牆上那種正式食譜卡，**從來不提『桌上那罐鹽』**，因為它要拿到哪個廚房都能用。」

一張**不提桌上任何東西**的小紙條，也可以抄成正式食譜卡。但「看一眼桌上那罐鹽」的紙條，就沒辦法抄成正式卡。

> 這就是 **`fn` 函式指標**：`let mul: fn(i32, i32) -> i32 = |a, b| a * b;`。只有**不捕獲任何東西**的閉包能變成 `fn`。所有 `fn` 也都實作 `Fn`，可以傳給要 `Fn` 的地方。

## 回到現實：故事 ↔ Rust 對照表

| 故事裡的東西 | 真正的 Rust 概念 |
|------|------|
| 牆上的食譜卡 | **函式** `fn add` |
| 放進去的材料 / 端出來的盤子 | **參數** / **回傳值** |
| 有句點的步驟 | **statement**（有 `;`） |
| 沒句點的最後一盤 | **expression** = 回傳值 |
| 蛋壞了直接端出 0 | **`return`** 早返 |
| 隨手寫的小紙條 | **閉包** `\|x\| x + 1` |
| 紙條提到桌上的東西 | **捕獲環境** |
| 只看一眼鹽罐 | **`Fn`**（借 `&T`） |
| 在記分板上畫一筆 | **`FnMut`**（借 `&mut T`） |
| 用掉最後一顆蛋 | **`FnOnce`**（消耗 `T`） |
| 香草精裝進便當盒帶走 | **`move`** 閉包 |
| 三位幫手的工作條件 | `F: Fn` / `F: FnMut` / `F: FnOnce` |
| 輸送帶照紙條處理每片 | **高階函式** `map` / `sum` |
| 放好 10 的專屬小機器 | **`make_adder` → `impl Fn`** |
| 裝進一樣大的紙箱 | **`Box<dyn Fn>`** |
| 不提桌上東西的正式卡 | **`fn` 函式指標** |

---

## 一句話記住

> **函式是牆上的食譜卡，最後沒句點的那一盤就是成品；閉包是會記得桌上東西的小紙條：只看一眼是 `Fn`、會改東西是 `FnMut`、會用掉東西是 `FnOnce`，而 `move` 只是把東西裝進便當盒帶走，不代表只能用一次。**
