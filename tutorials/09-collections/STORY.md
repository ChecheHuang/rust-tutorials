# 故事版：園遊會攤位的收納大作戰 🎪

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「班上辦園遊會、要整理一堆東西」的故事，幫你「感覺」出 `Vec`、索引與 `get`、容量、`HashMap` 與 `entry`、`HashSet` 與集合運算、`BTreeMap`、`VecDeque`、`collect` 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 一長條的編號格子盒

園遊會前一天，小安負責「彈珠攤」。老師給他一個**長條形的格子盒**，格子從 **0 號**開始一格一格排下去，全部**緊緊連在一起**。

小安放進第一顆彈珠、第二顆、第三顆——每次都放在**最後面**。要拿走的時候，也是從最後面拿最方便。

> 這就是 **`Vec<T>`**：一排連續的格子，最常在尾巴放（`v.push(1)`）、尾巴拿（`v.pop()`）。`vec![10, 20, 30]` 是一次放好三顆的快速寫法。`v.insert(0, 0)`、`v.remove(2)` 在中間插入或拿走，後面的彈珠要**全部挪一格**，所以比較慢。

---

## 伸手亂抓 vs 先問一聲

弟弟跑來說：「我要**第 99 格**的彈珠！」可是盒子只有 3 格。

**第一種弟弟**直接伸手去抓第 99 格——抓到空氣，嚇得大叫，整個攤位**停下來**。

**第二種弟弟**先問：「第 99 格**有沒有**東西？」小安回答：「**沒有喔。**」弟弟點點頭，去玩別的。

> 這就是 **索引 `v[i]` vs `v.get(i)`**：`v[99]` 超出範圍會 **panic**；`v.get(99)` 回傳 `Option<&T>`，沒有就給 `None`，安全又冷靜。程式裡 `println!("v.get(99) = {:?}", v.get(99))` 印出來就是 `None`。不確定格子在不在的時候，用 `get`。

---

## 先準備大盒子

小米負責「糖果攤」，她知道今天會收到**一千顆**糖果。

如果拿小盒子，每次滿了就要換更大的盒子、把糖果全部倒過去，好累。所以她一開始就拿一個**一千格的大盒子**——雖然現在裡面一顆都沒有。

> 這就是 **容量 `Vec::with_capacity(1000)`**：`len()` 是「放了幾顆」（0），`capacity()` 是「盒子有幾格」（至少 1000）。先準備好，就不用一直搬家（realloc）。

### 一邊數一邊加，手指會指錯

小安一邊用手指**一格一格數彈珠**，一邊想再塞新彈珠進去。老師馬上阻止：「不行！盒子滿了要換新盒子，你的手指就會指著**舊盒子的空位**！」

> 這就是 **借用規則保護集合**：`for x in &v { v.push(...) }` 編譯不會過。數的時候借了 `&v`，`push` 要 `&mut v`，兩個衝突；而且 push 可能換新的記憶體，舊的借用會失效。Rust 在**編譯時**就擋下來。

---

## 寫名字的集點簿

園遊會有「集點換獎品」。班長拿一本**集點簿**，每一頁上面寫一個**名字**，下面寫**點數**。

要查 alice 有幾點？直接翻到「alice」那頁，不用從第一頁一頁頁找，超快。

> 這就是 **`HashMap<K, V>`**：用「名字」（key）找「點數」（value）。`scores.insert("alice".into(), 95)` 寫一頁，`scores.get("alice")` 查一頁，找不到也是回 `None`。

### 有就加一，沒有就開新頁

carol 第一次來蓋章。班長不用先翻「有沒有 carol 這頁？」再決定要不要新增——他有一個口訣：

「**翻到 carol 那頁；沒有的話，就開一頁從 0 開始。然後加 1。**」

carol 來兩次，就變成 2 點。

> 這就是 **`entry` API**：`*scores.entry("carol".into()).or_insert(0) += 1;` 一次就完成「查、沒有就建、然後改」，是 Rust 計數的標準寫法。

### 集點簿的頁碼是亂的

大家翻集點簿時發現：頁面**不是照名字順序**排的，每次印出來的順序也可能不一樣。班長說：「這本是為了**找得快**，不是為了排整齊。」

> 這就是 **HashMap 不保證順序**：`for (name, score) in &scores` 的順序不固定，測試別依賴它。

---

## 簽到簿：同一個人只算一次

攤位門口有一本**簽到簿**，只在乎「**來過沒有**」。

小安簽了「rust」、「systems」，然後又簽了一次「rust」——簽到簿還是只有**兩個名字**，重複的不算。

後來兩個社團比對名單：
- **兩邊都有**的人（交集）
- **任一邊有**的人（聯集）
- **只在 A 社團**的人（差集）

> 這就是 **`HashSet<T>`**：自動去重、`tags.contains("rust")` 超快。`a.intersection(&b)`、`a.union(&b)`、`a.difference(&b)` 就是交集、聯集、差集。

---

## 按號碼排好的頒獎單

最後要頒獎。主持人拿到的是一張**按號碼排好**的名單：1 號、2 號、3 號……就算當初是先登記 3 號、再登記 1 號，名單上也自動排好了。

> 這就是 **`BTreeMap<K, V>`**：跟 HashMap 一樣用 key 找 value，但**永遠依 key 排序**。程式先 insert 3、1、2，`for (k, v) in &btm` 印出來還是 1、2、3。需要排序或範圍查詢（`range(2..)`）就用它。

---

## 棉花糖攤的隊伍

棉花糖攤大排長龍。一般人從**後面**排進來；但值日生要先拿，老師讓他從**前面**插進去。做好一支，就從**最前面**叫一個人走。

如果用那條長條格子盒來排隊，每次前面走一個人，**後面所有人都要往前挪一格**，太慢了。所以棉花糖攤用的是一條**兩頭都能進出的隊伍**。

> 這就是 **`VecDeque<T>`**：`q.push_back(1)`、`q.push_front(0)`、`q.pop_front()`，兩端進出都很快。要做先進先出的隊伍，用它，不要用 `Vec::remove(0)`。

---

## 倒進你指定的容器

收攤時，大家把散落一地的東西集中起來。老師說：「**你拿什麼盒子來，我就幫你裝成那個樣子。**」

拿長條盒來，就裝成一排；拿集點簿來，就把「名字—點數」一對對寫進去。

> 這就是 **`collect`**：`let from_iter: Vec<i32> = (1..=5).collect();`、`let map_from_pairs: HashMap<&str, i32> = [("a", 1), ("b", 2)].into_iter().collect();`。**你寫的目標型別**決定它裝成什麼。

## 回到現實：故事 ↔ Rust 對照表

| 故事裡的東西 | 真正的 Rust 概念 |
|------|------|
| 長條編號格子盒 | **`Vec<T>`** |
| 從尾巴放、尾巴拿 | `push` / `pop` |
| 中間插入，後面全部挪一格 | `insert` / `remove`（O(n)） |
| 伸手抓第 99 格，攤位停擺 | `v[99]` → **panic** |
| 先問「有沒有」 | `v.get(99)` → `Option<&T>` |
| 一開始就拿一千格的大盒子 | `Vec::with_capacity(1000)` |
| 放了幾顆 / 盒子幾格 | `len()` / `capacity()` |
| 一邊數一邊塞，手指會指錯 | 借用規則擋住 iterate 時 `push` |
| 寫名字的集點簿 | **`HashMap<K, V>`** |
| 「沒有就開新頁從 0，然後加 1」 | `*map.entry(k).or_insert(0) += 1` |
| 集點簿頁序亂的 | HashMap **不保證順序** |
| 簽到簿，重複不算 | **`HashSet<T>`** |
| 兩個社團比對名單 | `intersection` / `union` / `difference` |
| 按號碼排好的頒獎單 | **`BTreeMap<K, V>`** |
| 兩頭都能進出的隊伍 | **`VecDeque<T>`** |
| 拿什麼盒子就裝成什麼樣 | **`collect`**（看目標型別） |

---

## 一句話記住

> **一排東西用 `Vec`（不確定格子在不在就用 `get`）、用名字找東西用 `HashMap`（計數用 `entry().or_insert(0)`）、只在乎有沒有用 `HashSet`、要排好順序用 `BTreeMap`、兩頭排隊用 `VecDeque`，最後用 `collect` 倒進你要的盒子。**
