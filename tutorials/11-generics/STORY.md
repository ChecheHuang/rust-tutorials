# 故事版：萬用便當盒工坊 🍱

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「在便當盒工坊設計萬用盒子」的故事，幫你「感覺」出泛型函式、trait bound、`where`、泛型 struct / enum、特定型別才有的 method、monomorphization、`Default`、const generics 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 一直寫一樣的說明書

小傑在阿姨開的**便當盒工坊**打工。阿姨要他寫「**找出最大的那一個**」的工作說明書。

第一天他寫：「找出**最大的蘋果**。」
第二天又寫：「找出**最大的數字**。」
第三天再寫：「找出**字典裡排最後的單字**。」

三張說明書內容幾乎一模一樣，只差「蘋果、數字、單字」這幾個字。小傑煩死了。

阿姨說：「那就寫**一張**，把要比的東西留一個空格，叫它『**某樣東西**』就好。」

> 這就是 **泛型函式**：`fn largest<T: PartialOrd + Copy>(slice: &[T]) -> T`。`<T>` 就是那個「某樣東西」的空格。程式裡同一個 `largest` 可以用在 `largest(&ints)` 和 `largest(&strs)`。

---

## 空格不能隨便填

小傑很開心，拿著說明書去找「最大的**雲**」。結果卡住了——雲**沒辦法比大小**，也**沒辦法抄一份**放在手上。

阿姨說：「所以說明書上要寫清楚條件：『這個空格只能填**能比大小**、而且**能隨手抄一份**的東西。』」

> 這就是 **trait bound**：`T: PartialOrd + Copy`。`PartialOrd` 是「能比大小」（才能 `x > max`），`Copy` 是「能隨手抄一份」（才能 `let mut max = slice[0]`）。條件用 `+` 串起來。填不符合條件的型別，**編譯時**就會被擋下來。

### 條件太多，寫到背面

有些說明書條件一大串，寫在標題上擠成一團。阿姨教小傑：「標題只寫『某樣東西』，條件**寫到下面**另外列出來。」

> 這就是 **`where` 子句**：`fn print_all<T>(items: &[T]) where T: Debug + Clone`。意思一樣，只是比較好讀。

---

## 兩格便當盒

工坊最暢銷的是**雙格便當盒**：左格、右格。

左格可以放飯、右格放滷蛋；也可以左格放數字 3、右格放「hello」紙條。**左右兩格可以放不一樣的東西**。

每個雙格盒都有一個功能：「**把兩格的東西秀給客人看**」——只要兩格的東西都**能被描述出來**就行。

> 這就是 **泛型 struct**：`struct Pair<A, B> { first: A, second: B }`，`A`、`B` 是兩個不同的空格。`impl<A: Debug, B: Debug> Pair<A, B> { fn show(&self) }` 讓所有「兩格都能 Debug」的盒子都有 `show`。程式裡 `Pair { first: 3, second: "hello" }.show()`。

---

## 只有兩格都是數字才能「加總」

有些客人問：「可以把兩格**加起來**嗎？」

阿姨想了想：「只有**兩格都裝數字**的盒子才能加總。左邊飯、右邊滷蛋，要怎麼加？」

所以「加總按鈕」只裝在**數字專用款**上。

> 這就是 **只對特定型別的 impl**：`impl Pair<i32, i32> { fn sum(&self) -> i32 }`。這個 impl 沒有寫 `<A, B>`，因為它**只**給 `Pair<i32, i32>`。`Pair { first: 10, second: 20 }.sum()` 可以；`Pair { first: 3, second: "hello" }` 就沒有 `sum`。

---

## 一盒裝一盒的套盒

工坊還做**俄羅斯套盒**：一個盒子打開，可能是**一個小點心**（到底了），也可能是**左右兩個更小的盒子**，每個小盒子又可以繼續打開……

不管點心是餅乾還是糖果，套盒的做法都一樣。

> 這就是 **泛型 enum**：`enum Tree<T> { Leaf(T), Node(Box<Tree<T>>, Box<Tree<T>>) }`。`Leaf` 是點心、`Node` 是兩個小盒子。標準函式庫的 `Result<T, E>`、`Option<T>` 也都是泛型 enum。

---

## 能加、而且能抄

小傑又寫了一張「**把兩個東西加起來**」的說明書。條件是：「這東西要**能相加**，而且**加完還是同一種東西**；還要**能抄一份**，因為加的時候會把原本的用掉。」

3.5 加 2.5 可以，3 加 4 也可以。

> 這就是 **多重 bound**：`fn add_two<T: Add<Output = T> + Copy>(a: T, b: T) -> T`。`Add<Output = T>` 表示 `a + b` 的結果還是 `T`。程式裡 `add_two(3.5, 2.5)` 和 `add_two(3i32, 4)` 都能用。

---

## 開工前，工坊偷偷做好每一套模具

小傑以為：一張萬用說明書，工廠就用**同一套模具**慢慢調整。

阿姨帶他去後面看——原來每次接到訂單之前，工坊已經**照著萬用說明書，替每一種東西各做了一套專用模具**：「數字專用」「單字專用」……生產時直接用專用模具，**一點都不用停下來想**。

缺點是倉庫裡的模具變**很多**，做模具也要花時間。

> 這就是 **monomorphization（單態化）**：編譯器在**編譯期**為每個用到的 `T` 產生一份特化版本（`largest` 的 `i32` 版、`&str` 版）。好處：執行時零額外成本，跟手寫專用版一樣快；壞處：binary 變大、編譯變慢。想要「一份模具通用、執行時再看是誰」，要用下一章的 `dyn Trait`。

---

## 出廠的空盒子

每種盒子都有一個「**出廠狀態**」：數字盒出廠是 0、紙條盒出廠是空白紙條、長條盒出廠是空的。

客人只要說「給我一個**出廠的**」，工坊看他要哪一種盒子，就給他那種的出廠狀態。

> 這就是 **`Default` trait**：`let zero: i32 = Default::default();`、`String::default()`、`Vec::default()`。**你宣告的型別**決定拿到哪一種預設值。`#[derive(Default)]` 可以自動做出來。

---

## 五格蛋盒和三格蛋盒

最後，工坊做**蛋盒**。阿姨說：「五格蛋盒和三格蛋盒，是**不同的盒子**。格數是盒子身分的一部分。」

不過「**把蛋盒裡的蛋數一數、秀出來**」的說明書，只要寫一張，格數也留一個空格就好。

> 這就是 **const generics**：`fn print_array<const N: usize>(arr: &[i32; N])`。空格不只能填「種類」，也能填「**數字**」。`print_array(&arr_5)` 時 `N = 5`，`print_array(&arr_3)` 時 `N = 3`。`[i32; 5]` 和 `[i32; 3]` 是不同型別。

---

## 回到現實：故事 ↔ Rust 對照表

| 故事裡的東西 | 真正的 Rust 概念 |
|------|------|
| 只寫一張、留「某樣東西」空格 | **泛型函式** `fn largest<T>` |
| 空格只能填能比大小、能抄一份的 | **trait bound** `T: PartialOrd + Copy` |
| 條件寫到下面 | **`where` 子句** |
| 左右可放不同東西的雙格盒 | **泛型 struct** `Pair<A, B>` |
| 兩格都能描述就能「秀出來」 | `impl<A: Debug, B: Debug> Pair<A, B>` |
| 只有數字款才有加總按鈕 | `impl Pair<i32, i32> { fn sum }` |
| 一盒裝一盒的套盒 | **泛型 enum** `Tree<T>` |
| 能相加、加完同一種、能抄 | `T: Add<Output = T> + Copy` |
| 開工前替每種東西各做一套模具 | **monomorphization**（編譯期特化） |
| 模具變很多 | binary 變大、編譯變慢 |
| 出廠狀態 | **`Default::default()`** |
| 五格蛋盒、三格蛋盒是不同盒子 | **const generics** `<const N: usize>` |

---

## 一句話記住

> **泛型就是只寫一張留空格的說明書，trait bound 規定空格能填什麼；開工前（編譯期）工坊會替每種東西各做一套專用模具，所以跑起來跟手寫一樣快。**
