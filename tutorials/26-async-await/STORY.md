# 故事版：早餐店老闆娘的點餐單 🍳

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「早餐店老闆娘一個人顧很多客人」的故事，幫你「感覺」出 `async fn`、Future 為什麼是「懶」的、`.await`、順序 vs `join!` 並發、`spawn`、`select!`、`poll` 與 `Ready` / `Pending`、為什麼要 executor，以及 `async move` 和 `try_join!`。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 一個人顧一間店

巷口有一間早餐店，老闆娘叫**阿芳**。早上七點，店門口排了二十個客人。

隔壁的漢堡店做法不一樣：**一個客人配一個店員**。二十個客人就請二十個店員，每個店員站在煎台前**盯著自己那顆蛋**，蛋還沒熟就什麼也不做。店裡擠得要命，薪水也付不起。

阿芳只有一個人，但她很聰明：蛋放上煎台以後，**不用站在那邊盯**，她轉身去烤吐司、倒奶茶、收錢。哪個東西好了，她再回來處理。

> 這就是 **async 的用意**：OS thread（一個客人一個店員）每個要 ~2MB stack，上萬條吃不消。async 讓**一個 OS thread** 輪流照顧很多 task，遇到要等的 IO（煎蛋）就先去做別的事。

---

## 寫好的點餐單，不會自己變成早餐

客人小傑說：「我要一份蛋餅。」阿芳在**點餐單**上寫好：「蛋餅 ×1」。

然後……她把單子塞進口袋，就忘了。

十分鐘後小傑來問：「我的蛋餅呢？」阿芳拿出單子一看：「啊！單子寫好了，可是**我根本還沒開始做**。」

點餐單只是「**要做什麼**」的說明，寫好了不會自己跳上煎台。

> 這就是 **Future 是 lazy 的**：呼叫 `fetch_data(1)` 只是**建立一個 Future**（寫好點餐單），什麼都還沒做。`async fn fetch_data(id: u64) -> String` 背後其實是 `fn fetch_data(...) -> impl Future<Output = String>`。忘記 `.await`，編譯器會給你 `must_use` 警告——就像有人提醒「你口袋裡有張單子沒做喔」。

---

## 「我等你做好」

阿芳學乖了。她拿起單子說：「好，我現在就做，做好才換下一張。」

> 這就是 **`.await`**：`let a = fetch_data(1).await;` 把這個 Future 推進到完成，拿到結果 `"data-1"`。在等待時，`.await` 是一個「**可以先讓出位置**」的點，讓同一個 thread 去照顧別的 task。

---

## 一張一張做，好慢

小傑點了蛋餅，小蓁點了吐司。阿芳先煎蛋餅，**站在旁邊等到熟**，裝盒之後**才開始**烤吐司。

兩樣各要 200 秒，加起來等了 **400 秒**。

> 這就是 **順序執行（Sequential）**：`main` 的第一段，`let a = fetch_data(1).await; let b = fetch_data(2).await;`，a 完成才開始 b，總共約 400ms。

---

## 蛋餅和吐司一起做

第二天，阿芳把蛋餅放上煎台，**馬上轉身**把吐司放進烤箱。兩個一起在「等熟」，她兩邊來回看。

兩樣同時完成，**只花 200 秒**。而且，從頭到尾**還是只有阿芳一個人**。

> 這就是 **`tokio::join!`**：`tokio::join!(fetch_data(3), fetch_data(4))` 讓兩個 Future 在**同一個 task 裡**並發進行，約 200ms 就都好了。它不會跨 thread——是同一個人兩邊來回照顧。

---

## 請工讀生幫忙

週末客人更多，阿芳請了工讀生**小凱**。她把兩張單子撕下來，**直接交給店裡的工作團隊**，誰有空誰就做，然後拿一張取餐號碼牌回來。等一下她拿號碼牌去領成品就好。

> 這就是 **`tokio::spawn`**：`let h1 = tokio::spawn(fetch_data(5));` 把 Future 交給 runtime 當獨立的 task，可能跑在別的 OS thread 上。回傳 `JoinHandle`（號碼牌），`h1.await.unwrap()` 拿結果。因為可能被別人帶去做，這個 Future 必須是 `Send + 'static`（第 28 章）。

---

## 誰先好就先出

有個上班族說：「我只等 50 秒！你那份要做 100 秒的大餐我不要了，**50 秒內沒好我就走**。」

阿芳一邊做餐，一邊轉了一個 50 秒的計時器。結果計時器**先響**，上班族走了，阿芳就**把那份做到一半的餐丟掉**，不再做下去。

> 這就是 **`tokio::select!`**：`compute()` 要 100ms、`sleep(50ms)` 先完成，所以走 `"timeout first"` 那條路。贏的那個分支執行，**其他 Future 被 drop（取消）**。常用來做超時、競爭第一名。

---

## 「好了沒？」「還沒。」「好了沒？」「好了！」

阿芳怎麼知道蛋熟了沒？她會去**問**每一張單子：「你好了沒？」

- 單子回答「**還沒**」→ 她先去做別的，同時在煎台上放一個**小鈴鐺**。
- 蛋熟的時候，**鈴鐺叮一聲**，阿芳才回來再問一次。
- 單子回答「**好了，這是你的蛋餅**」→ 裝盒交給客人。

她不會每秒跑去問一次，那樣太累了；鈴鐺響了才回去。

> 這就是 **`Future` trait 與 `Poll`**：executor 呼叫 `poll(self: Pin<&mut Self>, cx: &mut Context)`，Future 回 `Poll::Pending`（還沒）或 `Poll::Ready(value)`（好了）。`cx` 裡的 **waker** 就是小鈴鐺：資源準備好時 `waker.wake()`，executor 才會再 poll。`async fn` 會被編譯成一個 state machine，每個 `.await` 是一個狀態。

---

## 沒有老闆娘，單子永遠是單子

如果店裡**一個人都沒有**，只有一疊寫好的點餐單呢？那就一份早餐都不會出來。

這個城市的規定很特別：**開店不附送老闆娘**，要自己去請。最多人請的是一位叫「**東京**」的專業店長。

> 這就是 **為什麼需要 runtime / executor**：Rust 標準函式庫**不提供** executor，要自己選，99% 選 `tokio`。`#[tokio::main]` 展開後是 `Runtime::new().unwrap().block_on(async { ... })`——請來店長，並且站在門口一直等到整個 `main` 的事情做完。

---

## 打包帶走的單子

阿芳想在單子上寫一句「**hello**」再出餐。她把寫著 hello 的小紙條**一起夾進單子裡**，這樣單子交給誰做，紙條就跟著走。

> 這就是 **`async move` 區塊**：`let say = async move { ... println!("{prefix} from async block"); };` 把 `prefix` 的所有權搬進 Future 裡。跟 closure 的 `move` 一樣，Future 帶著自己需要的東西。

---

## 套餐：一樣失敗就整份退

有客人點「蛋餅＋奶茶」套餐。阿芳兩樣一起做，**任何一樣出包**（例如奶茶打翻）就直接告訴客人：「這份套餐做不成。」

> 這就是 **`tokio::try_join!`**：`may_fail(false), may_fail(true)` 其中一個回 `Err("oops")`，整個結果就是 `Err("oops")`。兩個都 `Ok` 才回 `Ok(("ok", "ok"))`。

## 回到現實：故事 ↔ Rust 對照表

| 故事裡的東西 | 真正的 Rust 概念 |
|------|------|
| 一個客人一個店員 | **OS thread**（`std::thread::spawn`） |
| 阿芳一個人顧很多客人 | **async**：一個 thread 輪流跑很多 task |
| 煎蛋要等熟 | **IO 等待**（`sleep` 模擬） |
| 寫好但還沒做的點餐單 | **Future**（lazy） |
| 「點餐單」的寫法 | `async fn` → `impl Future<Output = T>` |
| 「我現在做，做好再說」 | **`.await`** |
| 一張一張做 | **順序執行** |
| 蛋餅吐司一起做（還是一個人） | **`tokio::join!`** |
| 交給工作團隊＋拿號碼牌 | **`tokio::spawn`** → `JoinHandle` |
| 50 秒沒好就走，做一半的丟掉 | **`tokio::select!`**（輸家被 drop） |
| 「好了沒？」 | **`poll`** |
| 「還沒」/「好了」 | `Poll::Pending` / `Poll::Ready(v)` |
| 煎台上的小鈴鐺 | **Waker**（`cx`） |
| 開店不附送老闆娘 | std 沒有 executor |
| 專業店長「東京」 | **tokio** runtime |
| 站在門口等到收工 | `#[tokio::main]` → `block_on` |
| 夾進單子的小紙條 | **`async move`** |
| 套餐一樣失敗就整份退 | **`tokio::try_join!`** |

---

## 一句話記住

> **Future 是一張寫好的點餐單：不 `.await`、沒人 poll，就永遠不會變成早餐；`join!` 是一個人兩邊一起顧，`spawn` 是交給團隊，`select!` 是誰先好就走、其他丟掉——而老闆娘（runtime）要自己請。**
