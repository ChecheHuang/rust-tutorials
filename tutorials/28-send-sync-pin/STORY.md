# 故事版：社區大樓的管理員伯伯 🏢

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「社區大樓裡大家借東西、共用東西、搬東西」的故事，幫你「感覺」出 `Send`、`Sync`、為什麼 `Rc` 和 `RefCell` 不能跨執行緒、`Arc`、async 裡的 Send 病毒、`std::sync::Mutex` vs `tokio::sync::Mutex`、`Pin` / `Unpin`、`pin!` 和 `'static`。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 兩種「可以」

阿哲住在幸福社區大樓。一樓有位**管理員伯伯**，他手上有一本規則簿，專門判斷兩件事：

1. 這個東西**能不能整個交給別戶的人帶走**？
2. 這個東西**能不能讓好幾戶的人同時拿來看**？

例如阿哲的**故事書**：交給樓上的小蓉帶回家，沒問題；擺在交誼廳讓大家一起翻，也沒問題。

伯伯說：「一個東西能讓大家同時看，其實就等於『**看它的權利**』可以交給別人。」

> 這就是 **`Send` 與 `Sync`**：`T: Send` 表示 T 可以 **move 到另一條 thread**；`T: Sync` 表示 **`&T` 可以跨 thread 共享**。關係是 **`T: Sync` ⟺ `&T: Send`**。兩個都是 **marker trait**，沒有任何方法，只是給編譯器看的標籤。`send_ok()` 把 `String` move 進 `thread::spawn`，就是「交給別人帶走」。

---

## 箱子裡每樣都 OK，箱子才 OK

阿哲要寄一個箱子給住在別棟的阿嬤。伯伯打開箱子檢查：故事書 OK、毛衣 OK、餅乾 OK。「好，**整箱都可以寄**。」

如果箱子裡有一樣不能寄的，**整箱都不能寄**。

> 這就是 **自動推導規則**：所有 field 都 `Send` → 這個型別就 `Send`；所有 field 都 `Sync` → 就 `Sync`。你不用自己寫 impl，編譯器會自動判斷。`i32`、`String`、`Vec<T>`、`HashMap` 都是兩者皆有。

---

## 手寫的借用次數卡

交誼廳有一台**共用的吹風機**，旁邊掛著一張**紙卡**，記錄「現在有幾戶人家正在用」。每借一次就在卡上**加一筆**，還回來就**擦掉一筆**；擦到零，吹風機就收起來。

這招在**自己家裡**很好用，因為一次只有一個人會去改紙卡。

可是有一天，阿哲和小蓉**同時**跑來，兩人都看到卡上寫「2」，兩人都改成「3」。其實應該是 4！後來大家陸續歸還，數字擦到零的時候，**還有人正在用**，吹風機卻被收走了。

伯伯換了一台**電子計數器**：按鈕一次只能一個人按，按下去就準確加一，絕對不會亂掉。這台就能讓整棟大樓共用。

> 這就是 **`Rc` vs `Arc`**：`Rc::clone` 加減引用計數是**非 atomic** 的，兩條 thread 同時改會 race，所以 `Rc` **既不 `Send` 也不 `Sync`**。`Arc` 用 **atomic** 加減，所以 `Arc<T>` 在 `T: Send + Sync` 時可以跨 thread。`sync_ok()` 用 `Arc::new(vec![1, 2, 3])` 再 `Arc::clone(&v)` 給三條 thread 一起讀。

## 自己記「誰在改」的便條

阿哲家有一本**筆記本**，封面貼著一張便條：「現在有人在寫嗎？」要寫之前先看便條，寫完再撕掉。

這本筆記本**整本交給**小蓉帶回家用，沒問題——到她家以後，也只有她一個人在看那張便條。

可是如果把它放在交誼廳**讓大家同時用**，兩個人同時看便條、都以為「沒人在寫」，就會同時下筆，寫得亂七八糟。

> 這就是 **`RefCell` 是 `Send` 但不是 `Sync`**：`borrow_mut()` 檢查的內部 counter 不是 atomic。整個 `RefCell` move 給另一條 thread 沒問題，但共享 `&RefCell` 不安全。`Cell<T>` 也一樣。

## 伯伯在門口把你攔下來

阿哲想把吹風機的**紙卡**塞進箱子寄給阿嬤。伯伯在門口直接攔下：「這張紙卡**不能**寄到別戶去！」

他不是等出事才罵人，而是**在出門前就擋住**。

> 這就是 **編譯期錯誤**：寫 `thread::spawn(move || println!("{r}"))` 搬一個 `Rc` 過去，會得到 `` `Rc<i32>` cannot be sent between threads safely ``。看到「cannot be **sent**」= 缺 `Send`；看到「cannot be **shared**」= 缺 `Sync`。所有 data race 都在**編譯時**被擋下。

## 打包好的待辦信封

社區有一種**待辦信封**：裡面裝著「要做的事」和「做到一半需要的東西」。信封可以自己做，也可以**交給志工團**做——志工團的人可能住在別棟。

阿哲的信封寫著：「拿吹風機紙卡 → **先去倒垃圾（要等）** → 回來看紙卡上的數字」。

因為「等倒垃圾」的時候紙卡還**夾在信封裡**，伯伯說：「這封**不能**交給志工團，紙卡不能出門。你自己做就可以。」

解法有三個：換成電子計數器；或者**在等待之前就把紙卡用完放回去**；或者只在自己家裡做。

> 這就是 **async 的 Send 病毒**：`async_with_rc()` 裡的 `Rc` 跨過 `yield_now().await`，所以整個 Future（state machine）含有 `Rc`，**不是 `Send`**。直接 `.await` 沒問題，但 `tokio::spawn(async_with_rc())` 會編譯失敗。改用 `Arc::new(42)` 就能 spawn。其他修法：讓 `Rc` 在 `.await` 前離開 scope，或用 `LocalSet` + `spawn_local`。

## 抓著門把等 vs 拿號碼牌排隊

社區只有**一間洗衣間**。

舊規則：要用的人**抓著門把**等，抓到了才進去。如果你進去之後說「我等一下要去樓下拿洗衣精」，你出門時**還抓著門把不放**，整條走廊的人都卡住，而且那個門把不准帶出大樓。

新規則：發**號碼牌**。輪到你才進去，你可以拿著號碼牌去樓下拿洗衣精再回來，等的人也能先去做別的事。

> 這就是 **`std::sync::Mutex` vs `tokio::sync::Mutex`**：std 的 `lock()` 會 block 整條 thread，`MutexGuard` 不是 `Send`，**跨 `.await` 持有**會出問題。`tokio::sync::Mutex` 的 `lock().await` 不 block thread，guard 可以跨 await。經驗法則：鎖只在同步程式碼內 → std（較快）；要跨 await → tokio。

## 寫著門牌號碼的紙條

小蓉家要**搬家**。她把一個紙箱打包好，裡面放了一串鑰匙，還有一張紙條寫著：

> 「鑰匙在**幸福路 5 號 3 樓、這個箱子**的左邊口袋。」

紙條和鑰匙都在**同一個箱子**裡。如果箱子被搬到新家（**和平路 8 號**），紙條還寫著「幸福路 5 號」——照著紙條去找，**找到的是舊家的空房間**！

所以搬家公司說：「這種箱子**一旦開始用了**，就要**釘在地上**，誰都不准搬。」

> 這就是 **Pin**：`async` 產生的 Future 可能是 **self-referential**——狀態機裡同時有 `buf` 和指向 `buf` 的引用。Future 被 move 到別的記憶體位址，內部的引用不會更新，就指錯地方。`Pin<P>` 承諾「**這個值不會再被搬動**」，所以 `Future::poll` 收的是 `Pin<&mut Self>`。

---

## 搬了也沒差的東西，和兩種釘法

大部分的箱子裡**沒有這種寫門牌的紙條**，搬來搬去都沒差，伯伯就不用管它們。

真的需要釘住的箱子，有兩種釘法：

- **釘在自己家的地板**上：最快，不用另外租地方。
- **寄放到社區倉庫**，在倉庫裡釘住：之後要帶著「倉庫寄放單」到處走也可以。

> 這就是 **`Unpin` 與 `pin!` / `Box::pin`**：多數型別實作 `Unpin`（搬了沒差），async block 產生的 Future 則不是。`pin_demo()` 用 `std::pin::pin!(fut)` 把 Future **釘在 stack 上**，再 `fut.as_mut().await`。`Box::pin(future)` 是釘在 heap 上，適合存進 struct（`Pin<Box<dyn Future<Output = i32> + Send>>`）。99% 情況 `.await` 和 `tokio::spawn` 都幫你處理好了。

---

## 交出去的東西不能是借來的

志工團接下信封後，**什麼時候做完沒人知道**，可能阿哲早就搬走了。

所以伯伯規定：信封裡**不能放「跟阿哲借的東西」**，只能放**整個送給志工的東西**。不然阿哲搬走以後，借的東西就沒有主人了。

> 這就是 **`'static` bound**：`tokio::spawn` 要 `F: Future + Send + 'static`。spawn 出去的 task 可能比父 scope 活得更久，所以不能借用父 scope 的變數（除了 `&'static`）。解法是用 `async move` 把資料的所有權搬進去。

## 回到現實：故事 ↔ Rust 對照表

| 故事裡的東西 | 真正的 Rust 概念 |
|------|------|
| 能整個交給別戶帶走 | **`Send`** |
| 能讓好幾戶同時看 | **`Sync`**（`&T: Send`） |
| 管理員伯伯的規則簿 | **編譯器** + marker trait |
| 箱子裡每樣 OK 才能寄 | **自動推導**（所有 field 都 Send/Sync） |
| 手寫的借用次數紙卡 | **`Rc<T>`**（非 atomic 計數） |
| 電子計數器 | **`Arc<T>`**（atomic 計數） |
| 自己記「誰在改」的便條 | **`RefCell<T>`**（Send、不 Sync） |
| 伯伯在門口攔下 | **編譯錯誤** `cannot be sent between threads` |
| 待辦信封 | **Future（state machine）** |
| 交給志工團 | **`tokio::spawn`** |
| 等待時紙卡還夾在信封裡 | `Rc` **跨 `.await`** → Future 非 Send |
| 抓著門把等 | **`std::sync::Mutex`** |
| 拿號碼牌排隊 | **`tokio::sync::Mutex`** |
| 寫門牌號碼的紙條 | **self-referential** Future |
| 釘在地上不准搬 | **`Pin`** |
| 搬了也沒差的箱子 | **`Unpin`** |
| 釘在自己家地板 / 社區倉庫 | **`pin!`**（stack）/ **`Box::pin`**（heap） |
| 信封裡不能放借來的東西 | **`'static`** bound |

---

## 一句話記住

> **`Send` 是「能交給別人帶走」，`Sync` 是「能讓大家一起看」；手寫紙卡（`Rc`）不能出門，要換電子計數器（`Arc`）；寫著自己門牌的箱子一開始用就要釘住（`Pin`），而交給志工團（`spawn`）的信封裡不能放借來的東西（`'static`）。**
