# 故事版：河濱公園的風箏日 🪁

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「全班去河濱公園放風箏」的故事，幫你「感覺」出所有權三條規則、move、Copy、Clone、把東西交給函式、從函式拿回東西、`drop()` 和 `Drop` 的收拾順序是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 公園的三條規定

風箏日一早，公園管理員伯伯拿著大聲公宣布：

1. 每一隻風箏，都有**一個**主人——就是**手上握著線軸**的那個人。
2. 同一個時間，一隻風箏**只能有一個**主人。
3. 主人**回家的時候**，他的風箏一定要**收下來**，不准留在天上。

「這樣，」伯伯說，「公園就不會有沒人管的風箏卡在樹上，也不會有兩個人搶著收同一隻。」

> 這就是 **所有權三條規則**：每個值有唯一 owner；同時只能有一個 owner；owner 離開 scope 時值被 drop。Rust 在**編譯期**檢查這三條，沒有 runtime 成本。

---

## 把線軸交出去

小風的風箏飛得好高。小晴說：「給我放放看！」

小風把**線軸**交給小晴。注意：天上的風箏**沒有變成兩隻**，它還是那一隻，只是線軸換到小晴手上。

現在小風想拉一下線——手上**什麼都沒有**。伯伯說：「線軸交出去，風箏就是小晴的了，你不能再拉。」

> 這就是 **move**：`let s1 = String::from("hello"); let s2 = s1;`。`String` 本身像線軸（ptr、len、cap 三個小東西），內容在 heap 上像天上的風箏。move 只把線軸交出去，**不會複製風箏**。之後再用 `s1` 會編譯錯誤：borrow of moved value。

### 為什麼不能兩個人都拿線軸？

如果小風和小晴**都覺得**自己是主人，傍晚兩個人都要回家，就會**兩個人都去收同一隻風箏**——一個人收好了，另一個人去拉一條已經沒有風箏的線，場面一團亂。

> 這就是 Rust 禁止「兩個 owner」的原因：避免 **double free**（同一塊記憶體被釋放兩次）。move 之後舊的變數直接失效，誰負責收拾永遠只有一個答案。

---

## 告訴你一個數字

小晴問小風：「你今天的**號碼布**是幾號？」

小風說：「**5 號**。」

小晴在自己的手背上寫了 5。現在**兩個人都知道** 5，小風也沒有因為說出來就「失去」他的號碼。這種很小、全部都在手上的東西，告訴別人就是**直接抄一份**，一點都不麻煩。

> 這就是 **Copy**：`let n1 = 5; let n2 = n1;` 之後 `n1`、`n2` 都能用。`i32`、`f64`、`bool`、`char`、全是 Copy 的 tuple 這種完全在 stack 上的小型別，複製就是照抄 bytes。

### 什麼東西能直接抄？

伯伯說：「**數字、號碼布**這種可以直接抄。但風箏不行——你抄了一張紙，天上也不會多出一隻風箏。」

「還有，」伯伯補充，「如果某樣東西**收拾的時候要做特別的事**（例如要先捲線、再折骨架），那它也不能隨便抄。」

> 這就是 **Copy 的條件**：要自己 opt-in（`#[derive(Copy, Clone)]`），而且只限純 stack 資料。`String`、`Vec`、`Box` 不能 Copy；有實作 `Drop` 的型別也**不能**同時是 Copy。

---

## 真的再做一隻

小晴說：「我也想要一隻**一模一樣**的風箏！」

小風帶她去手作攤位。攤位阿姨照著小風的風箏，**重新剪紙、重新綁骨架、重新畫圖案**，花了好久才做出第二隻。

現在天上真的有**兩隻**，各有各的線軸，各有各的主人。

> 這就是 **Clone**：`let s4 = s3.clone();`，真的把 heap 上的內容複製一份。Rust 規定一定要**親口說** `.clone()`，因為它可能很貴，不想讓你「不小心」複製一大堆。

---

## 交給評審

風箏比賽開始了。小風把自己的風箏（連線軸）**交給評審**。評審拿去量、拿去看，評完之後**評審就把它收起來**了——比賽規定交上去的風箏不退還。

小風想再看一眼：「我的風箏呢？」已經不在他手上了。

可是小風告訴評審自己的**號碼**時，評審抄下來，小風自己還是記得號碼。

> 這就是 **把值傳給函式**：`takes_ownership(s)` 會把 `s` move 進函式，函式結束時 `s` 就被 drop，外面不能再用。`makes_copy(n)` 傳的是 Copy 型別，`n` 外面照樣可用。想留著就 `.clone()`，或者**借**給函式看（下一章）。

### 抽獎送的風箏

比賽結束，攤位抽獎，小晴抽中一隻**新風箏**。阿姨把線軸交到她手上：「這隻現在是**你的**了。」

> 這就是 **回傳值轉移所有權**：`let gifted = gives_ownership();`，函式裡做出來的 `String` 交給呼叫者，`gifted` 就是新的 owner。

---

## 風太大，先收起來

下午風突然變好大。小風的**大型風箏**拉得他手好痠，他決定**不等回家**，現在就先收起來。

收好之後，那隻風箏就不在了，他也沒辦法再放。

> 這就是 **`drop(big)`**：`std::mem::drop` 只是一個普通函式，吃進所有權、讓它立刻離開 scope，用來**提早**釋放資源（特別是鎖）。注意你**不能**自己呼叫 `big.drop()`。

---

## 傍晚的收拾順序

小晴一到公園，先搭了一頂**大帳篷**。中午她在帳篷旁邊圍了一個**小野餐區**，掛了一盞**小燈籠**。

野餐結束，小野餐區一撤，小燈籠**馬上**被收起來，還發出「叮——燈籠收好了」的聲音。但大帳篷**還在**。

傍晚要回家了，才輪到大帳篷：「叮——帳篷收好了。」

伯伯說：「你們看，**後搭的先收，先搭的後收**。而且每樣東西收的時候要做什麼，是它**自己規定好的**，時間到了一定會做，不用你記。」

> 這就是 **`Drop` trait 與 RAII**：`impl Drop for LoudGuard { fn drop(&mut self) { ... } }`。`main` 裡 `_inner` 在內層 block 的 `}` 就印 `dropping inner`，`_outer` 到 `main` 結束才印 `dropping outer`。變數以**宣告的相反順序** drop。鎖、檔案、socket 都靠這招自動釋放。

---

## 隔壁公園的清潔隊

隔壁的公園沒有這三條規定。風箏放完就隨便丟在草地上，每隔一陣子，**清潔隊**會開車來繞一圈，把沒人要的風箏撿走。

清潔隊來的時候，整個公園要**暫停**讓他們工作，而且誰也不知道他們**什麼時候**會來。

> 這就是 **Rust vs GC 語言**：GC 由 runtime 決定何時回收（不確定、可能暫停）；Rust 在 scope 結束時**確定地**釋放，成本在編譯期就決定了。

## 回到現實：故事 ↔ Rust 對照表

| 故事裡的東西 | 真正的 Rust 概念 |
|------|------|
| 公園的三條規定 | **所有權三條規則** |
| 握著線軸的人 | **owner** |
| 天上的風箏 | **heap 上的資料** |
| 線軸（小小的） | `String` 的 **(ptr, len, cap)** |
| 把線軸交出去 | **move** `let s2 = s1;` |
| 交出去後手上空空 | 舊變數**失效**（borrow of moved value） |
| 兩個人搶收同一隻 | **double free**（Rust 禁止） |
| 告訴別人號碼布 | **Copy**（`i32` 等） |
| 有特別收拾方式的不能抄 | **Copy 與 Drop 互斥** |
| 手作攤位重做一隻 | **`.clone()`** |
| 交給評審、評審收走 | **`takes_ownership(s)`** move 進函式 |
| 告訴評審號碼 | **`makes_copy(n)`** |
| 抽獎送的新風箏 | **`gives_ownership()`** 回傳轉移 |
| 風太大先收起來 | **`drop(big)`** |
| 帳篷和燈籠自己規定的收法 | **`impl Drop for LoudGuard`** |
| 後搭的先收 | **宣告反序 drop** |
| 隔壁公園的清潔隊 | **GC** |

## 一句話記住

> **每隻風箏只有一個握線軸的主人：交出線軸就是 move，號碼這種小東西可以直接抄（Copy），想要第二隻就得親口說重做（`.clone()`）；主人一離開，風箏一定被收下來（Drop），後搭的先收。**
