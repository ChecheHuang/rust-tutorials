# 故事版：早餐店櫃台旁的小白板 🥪

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「早餐店櫃台旁邊有一塊小白板」的故事，幫你「感覺」出 Redis、連線管理、常用指令、TTL、cache-aside、原子計數、限流、Pub/Sub、Streams、分散式鎖和 Lua script 是什麼。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 後面的大帳本，前面的小白板

阿美阿姨開了一間早餐店。店後面的辦公室有一本**超厚的大帳本**，記著每位熟客的名字、愛吃什麼、欠多少錢。帳本很可靠，可是每次要查，都得**走到後面、翻好幾頁**，很慢。

於是阿美在**櫃台旁邊**掛了一塊**小白板**。常被問到的事，就寫在白板上，一轉頭就看得到。

白板很快，但它只是**方便用的小抄**：真正算數的，還是後面那本大帳本。

> 這就是 **Redis**：放在記憶體裡、超快的 key-value 資料庫，常拿來當 cache。真正的資料（source of truth）還是在 DB（大帳本）。Redis 有 RDB / AOF 存檔，但不是強耐久，**別把它當成唯一的帳本**。

---

## 一支會自己重撥的對講機

阿美的兒子小傑負責在廚房做餐，他跟櫃台之間用**一支對講機**聯絡白板上的事。

如果對講機斷線，它會**自己等一下再重撥**，不用小傑每次衝出來修。而且小傑不會每做一份餐就去買一支新對講機——**一支用到底**。

> 這就是 **`redis::Client::open(url)` + `ConnectionManager::new(client)`**：`ConnectionManager` 會自動重連、帶 backoff。**不要每個 request 都開新連線**。如果真的需要很多條並行，才用 `deadpool-redis` / `bb8-redis` 這類連線池。

---

## 白板上的各種寫法

白板上可以寫很多種東西：

- 「**今日特餐：蛋餅**」——寫上去、擦掉、再查。
- 「**豆漿剩 3 杯**」——還能直接加一、減一。
- 「**外送排隊：A 先、B 後**」——一條排隊的隊伍。
- 「**今天來過的熟客：小王、小李**」——不會重複的名單。
- 「**小王的早餐：蛋餅＋奶茶＋不要冰**」——一張小卡，裡面分好幾格。

> 這就是 **`AsyncCommands` 的常用指令**：`set` / `get` / `del` / `exists` 是一般字串；`incr` 是計數；`lpush` 是 list（隊伍）；`sadd` 是 set（不重複名單）；`hset` 是 hash（一張分格小卡）。回傳型別要標清楚，像 `let v: Option<String> = conn.get(key).await?;`。

## 會自己消失的字

阿美在白板上寫字時，常常順手畫一個**小沙漏**：「這行 60 秒後擦掉。」

時間一到，那行字就自己不見了。因為她知道：如果什麼都不擦，白板很快就會**塞滿過期的舊資訊**，最後什麼都看不清楚。

> 這就是 **TTL**：`conn.set_ex(key, value, 60)` 寫入時就給 60 秒壽命；`conn.expire(key, 30)` 重設壽命。常見陷阱第一名就是**忘了設 TTL**，cache 變成記憶體墓場。

## 先看白板，沒有再翻帳本

熟客小王走進來：「阿姨，我平常吃什麼？」

阿美**先轉頭看白板**：

- **白板上有寫**（中了！）→ 馬上回答。
- **白板上沒寫**（沒中）→ 走去後面翻大帳本，查到之後**順手抄到白板上**，再畫一個 60 秒的小沙漏，然後回答。

小王第二次問的時候，白板上已經有了，阿美一秒就答出來。

> 這就是 **cache-aside**：程式裡的 `cache_aside()` 先 `conn.get("user:42")`，有值就 `serde_json::from_str` 解出 `Session`（cache hit）；沒有就「假裝查 DB」，再用 `conn.set_ex(key, serde_json::to_string(&sess)?, 60)` 寫回去。`main` 呼叫兩次，第二次就 hit。

### 一群人同時問

有一天，一整台遊覽車的客人**同時**衝進來問同一件事，而白板剛好擦掉了。結果五十個人一起跑去後面翻帳本，辦公室擠爆。

阿美學乖了：第一個去翻帳本的人，在白板上先寫「**我去查了，等我**」，其他人就在前面等。

> 這就是 **cache stampede（快取雪崩）**：高併發同時 miss，全部打到 DB。對策有：用 SETNX + TTL 加鎖、在程式內合併相同請求（singleflight 風格）、或在 TTL 快到時提前背景刷新。

## 不會數錯的點餐計數器

早餐尖峰時，好幾個店員同時在白板上記「今天賣了幾份」。

如果每個人都是「看一眼數字 → 心算加一 → 擦掉寫新的」，兩個人同時看到 10，各自寫 11，就**少算了一份**。

所以阿美改用一個**按一下就加一的計數器**。不管多少人同時按，每按一次就是**確實加一**，絕不漏。

> 這就是 **原子計數 `incr`**：`counter_atomic()` 先 `del("api:hits")`，再呼叫五次 `conn.incr("api:hits", 1)`，結果一定是 5。Redis 在伺服器端一次做完「讀 + 加 + 寫」，不會被別人插隊。

---

## 十秒內最多點五次

有個調皮的小朋友一直按櫃台的點餐鈴，叮叮叮叮叮……

阿美在白板上幫每個人開一格：「**這位小朋友：0 次**」，旁邊畫一個 **10 秒的沙漏**。他每按一次就加一；超過 5 次，鈴就不響了。等 10 秒沙漏流完，那格自己消失，又可以重新按。

> 這就是 **fixed window 限流**：`rate_limit()` 對 `rl:{ip}` 做 `incr`，如果 `n == 1`（這格剛開）就 `expire(&key, 10)`，最後回傳 `n <= 5`。`main` 連打 7 次，第 6、7 次就是 `BLOCKED`。缺點是窗口交界可能瞬間爆量；更精準的有 sliding log（sorted set）和 token bucket（通常用 Lua 做成原子）。

## 店裡的廣播喇叭

阿美在店裡裝了一支**喇叭**。只要她喊「**12 號餐好了！**」，所有**正在店裡聽著**的人都會聽到。

可是如果 12 號客人剛好**跑去隔壁買報紙**，他就錯過了——喇叭不會幫他錄音，也不會再喊一次。

> 這就是 **Pub/Sub**：`pubsub_demo()` 裡用 `client.get_async_pubsub()` 再 `subscribe("events")`；另一個 task 用 `PUBLISH events hello-{i}` 喊三次；訂閱者從 `on_message()` 的 stream 收到並 `get_payload()`。Pub/Sub 是 **fire-and-forget**：不在線就收不到，不保證送達。

### 會留底的取餐單

後來阿美加了一疊**取餐單**：每張都有編號，一張一張往下疊。客人回來時可以說：「我看到第 37 張，給我後面的。」

> 這就是 **Redis Streams**：`XADD` 追加訊息、`XREAD` 讀取，搭配 `XGROUP` 消費者群組，訊息會留著、可以重讀。要可靠的訊息就用 Streams 或專業 MQ（第 44 章）。

## 只有一把的廚房鑰匙

後面的冷凍庫一次只能一個人進去。阿美在白板上規定：

「進去的人，先在白板寫『**冷凍庫：小傑，暗號 7788**』——**只有白板上那格是空的才能寫**，而且 30 秒後自動擦掉，免得有人忘了出來。」

出來的時候要擦掉，但**要先核對暗號是不是自己的**。不然小傑太慢出來、字已經過期、換阿明寫上去了，小傑一擦就把阿明的擦掉了。

> 這就是 **分散式鎖**：`SET resource unique_id NX PX 30000`，`NX` = 不存在才設、`PX` = 毫秒 TTL。釋放時要「比對 unique_id 再刪除」，而這兩步必須**一次完成**。

---

## 一口氣做完的小紙條

「核對暗號」和「擦掉」如果分兩次做，中間可能被別人插進來。

所以阿美寫了一張**小紙條**交給白板管理員：「如果那格寫的是 7788，就擦掉；不是就別動。」管理員拿到紙條，**一口氣做完**，中間誰都不能插隊。

> 這就是 **Lua script**：`redis::Script::new(r#"if redis.call("GET", KEYS[1]) == ARGV[1] then return redis.call("DEL", KEYS[1]) end return 0"#)`，再 `.key("lock").arg(token).invoke_async(&mut conn)`。Redis 會原子化執行整段腳本。對照之下，`MULTI` / `EXEC` 只是「打包不被插隊」，**沒有回滾**。

---

## 阿美的白板守則

1. 每行字都要畫沙漏（設 TTL）。
2. 一行別寫成一整面牆（避免大 key）。
3. 不要大喊「把白板上**所有**的字唸出來！」——全店都會停下來聽你唸（`KEYS *` 會阻塞，用 `SCAN`）。
4. 白板是小抄，帳本才是正本（Redis 不是唯一資料來源）。

## 一句話記住

> **Redis 是櫃台旁的小白板：先看白板、沒有再翻帳本並抄回去（cache-aside），每行都畫沙漏（TTL），計數用按一下就加一的計數器（`incr`），要一口氣做完的事寫成小紙條（Lua）——但真正的正本永遠是後面那本大帳本。**
