# 故事版：小學裡傳訊息的各種方法 🏫

> 這篇是**寫給小朋友也看得懂**的故事版。用一個「學校裡同學、老師、各班之間怎麼傳訊息、怎麼輪流用教室」的故事，幫你「感覺」出 `mpsc`、`oneshot`、`broadcast`、`watch` 四種 channel，以及 async 的 `Mutex`、`RwLock`、`Semaphore`、`Notify` 和 `CancellationToken`。故事裡不講程式名詞，名詞都放在 `>` 小框框和最後的對照表裡。先享受故事，別急著背。

---

## 意見箱：很多人投，一個人看

陽光國小的走廊上有一個**意見箱**。三個班的同學都可以把紙條投進去，可是只有**校長**一個人會打開來看。

意見箱不大，**最多只能放 8 張**。滿了的時候，想投的同學就得**在旁邊等一下**，等校長拿走幾張再投。

校長每天打開箱子，一張一張看。有一天，三個班的同學都**畢業了**，再也沒有人會投紙條。校長看完最後一張，就知道：「好，**不會再有新的了**。」

> 這就是 **`mpsc`（多個送、一個收）**：`mpsc::channel::<i32>(8)` 建立容量 8 的 channel，拿到 `(tx, rx)`。`mpsc_demo()` 裡三個 producer 各自 `tx.clone()` 再 `tx.send(v).await`。滿了 `send` 會等，這叫 **back-pressure**。所有 sender 都 drop 之後，`rx.recv().await` 回 `None`，所以程式裡要 `drop(tx)` 把主程式手上那支也丟掉，迴圈才會結束。

## 只能用一次的回條

老師請小彤去辦公室幫忙算一份成績，給她一張**回條**：「算好就把答案寫在上面交回來。」

回條**只有一張、只能交一次**。老師不用一直跑去看，只要**等回條回來**就好。

> 這就是 **`oneshot`**：`oneshot::channel::<String>()` 只能送一次。`oneshot_demo()` 裡 spawn 出去的 task 做完就 `tx.send("done".into())`（不用 await），主程式 `rx.await` 等結果。常見用法是把 `oneshot::Sender` 放進請求裡，讓 worker 回覆——就是 RPC pattern。

## 校園廣播：每一班都聽得到

早上八點，教務處打開**廣播**：「hello！」接著又說：「world！」

每一間有開喇叭的教室都**聽到一模一樣的內容**。想聽廣播的班級要先**接上喇叭**。

廣播站只會保留最近的幾段錄音。如果某一班太吵、一直沒在聽，等他們回過神來，前面的內容已經被新的蓋掉了，他們會知道「**我們漏聽了幾則**」。

> 這就是 **`broadcast`**：`broadcast::channel::<&str>(16)` 建立廣播，每個接收者用 `tx.subscribe()` 接上喇叭（`rx1`、`rx2`）。`tx.send("hello")` 會**複製**一份給每個訂閱者，所以訊息型別要 `Clone`。容量滿了會丟最舊的，太慢的接收者會收到 `Lagged` 錯誤。適合聊天室、事件 fan-out。

## 公布欄上的天氣牌

穿堂有一塊**天氣牌**，總務主任會一直更新：「晴天」→「多雲」→「下雨」。

同學經過時**只會看到現在掛著的那一張**。如果你剛好錯過「多雲」，那也沒關係，因為你在乎的只是**現在**的天氣。

有些同學會站在牌子前面等：「**換了再叫我**。」

> 這就是 **`watch`**：`watch::channel(0u64)` 建立一個「永遠只有最新值」的 channel。`watch_demo()` 裡 sender 依序 `tx.send(i)`，receiver 用 `rx.changed().await` 等它變，再用 `*rx.borrow()` 看現在的值。中間的值可能被跳過。適合 config reload、狀態通知。

## 體育器材室只有一把鑰匙

體育器材室只有**一把鑰匙**。十個班都要進去**把計分板加一分**。

一般的學校規定是「站在門口一直等，什麼事都不能做」。陽光國小的規定比較聰明：拿不到鑰匙的班級**先回教室做別的事**，輪到了會有人來叫。

而且拿到鑰匙的班級可以**拿著鑰匙去福利社一趟**再回來，因為其他人都不是在門口傻站著。

十個班都加完，計分板上是 **10 分**，一分都沒少。

> 這就是 **`tokio::sync::Mutex`**：`Arc::new(Mutex::new(0u64))` 包住共享資料，`locks_demo()` 裡 10 個 task 各 `m.lock().await` 再 `*g += 1`，最後是 10。`lock()` 是 async——拿不到時讓出 thread，不會卡住其他 task；guard 可以**跨 `.await` 持有**。代價是比 `std::sync::Mutex` 慢，所以只有跨 await 時才用它。

## 圖書館：大家一起看，修書要清場

圖書館的那本**百科全書**，很多同學可以**同時翻**。

可是圖書館阿姨要**補一頁**進去的時候，她會請大家先把書放下。等她補好，大家才能再看。

> 這就是 **`RwLock`**：`rw.read().await` 允許**多個讀者同時**持有（程式裡兩個 reader task 一起讀 `[1, 2, 3]`）；`rw.write().await` 是**獨佔**的，寫完 `push(4)` 之後再讀就是 `[1, 2, 3, 4]`。讀多寫少時比 Mutex 好。

## 電腦教室的座位牌

電腦教室只有 **10 個座位**。門口放著 10 張**座位牌**，拿到牌的人才能進去；用完了把牌放回來，下一個人才能拿。

> 這就是 **`Semaphore`**：`Semaphore::new(10)` 最多 10 個並發。`acquire_owned().await` 拿到 permit，drop permit 就歸還。限制同時打 API 的數量、限制 DB 連線都靠它。

## 上課鐘

午休時，小彤趴在桌上睡覺，跟同學說：「**鐘響了再叫我**。」

鐘一響，她就醒來了。這個鐘不用跟任何鑰匙綁在一起，就是單純的「**通知一聲**」。

> 這就是 **`Notify`**：一邊 `n.notified().await` 等，另一邊 `notify.notify_one()` 叫醒。像 condition variable，但不需要搭配 Mutex。

---

## 颱風假：一聲令下，全部停

颱風要來了。校長宣布：「**停課！**」

各年級主任收到，再告訴自己年級的每一班。每一班不管正在上什麼課，都馬上收書包回家。校長只要說一次，**整棵樹**一路傳下去。

> 這就是 **`CancellationToken`**（`tokio-util`）：`token.child_token()` 建立子 token，task 裡用 `tokio::select!` 同時等 `child.cancelled()` 和工作本身。`token.cancel()` 一次取消所有 child。graceful shutdown 的標準工具。

## 回到現實：故事 ↔ Rust 對照表

| 故事裡的東西 | 真正的 Rust 概念 |
|------|------|
| 意見箱（很多人投、校長看） | **`mpsc`** channel |
| 箱子最多放 8 張，滿了要等 | **bounded** channel、back-pressure |
| 同學都畢業，不會再有新紙條 | 所有 `tx` drop → `recv()` 回 `None` |
| 只能交一次的回條 | **`oneshot`** |
| 校園廣播 | **`broadcast`** |
| 接上喇叭 | `tx.subscribe()` |
| 每班聽到一模一樣的 | 訊息**複製**給每個 receiver（要 `Clone`） |
| 太吵漏聽了幾則 | `Lagged` 錯誤 |
| 公布欄的天氣牌 | **`watch`** |
| 「換了再叫我」 | `rx.changed().await` |
| 看現在掛的那張 | `rx.borrow()` |
| 器材室唯一的鑰匙 | **`tokio::sync::Mutex`** |
| 拿不到鑰匙先回教室做別的 | `lock().await` 讓出 thread |
| 拿著鑰匙去福利社 | guard **跨 `.await`** 持有 |
| 百科全書：大家看，修書清場 | **`RwLock`**（`read()` / `write()`） |
| 電腦教室座位牌 | **`Semaphore`** |
| 上課鐘 | **`Notify`** |
| 颱風假一路傳下去 | **`CancellationToken`** + `child_token()` |

---

## 一句話記住

> **很多人投、一個人看用意見箱（`mpsc`），只回一次用回條（`oneshot`），每班都要聽用廣播（`broadcast`），只在乎現在用天氣牌（`watch`）；要輪流用的東西拿鑰匙排隊（`Mutex` / `RwLock`），而排隊時記得先回教室做別的事（`.await`）。**
